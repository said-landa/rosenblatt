# Concepts

> Detailed counterpart: [LLM conceptual model](../llm/concepts.md)

This is the smallest vocabulary needed to discuss Machines without confusing a
real system, a course, a visual asset, and a learner record.

## Core map

```text
Learner -> follows Course -> teaches one primary Machine Variant
Course -> Chapter -> Lesson -> Assembly Step
Machine Variant -> Component -> nested Component
Component <-> functional Relation
Knowledge Concept -> explains Machine, Component, or Relation
Representation -> makes a semantic entity perceptible
Course Progress -> records durable traversal facts
Tutor Context -> projects the exact current learning situation
```

## Essential meanings

| Concept | Meaning |
| --- | --- |
| Machine | A bounded system whose related components cooperate to perform a function. |
| Machine Variant | The exact real-world configuration and boundary taught by a course. |
| Component | An identifiable physical, logical, or conceptual part with a function. A subcomponent is a recursively nested component. |
| Relation | A functional connection, dependency, flow, constraint, or transformation between components. |
| Course | A deliberate path for constructing and understanding one primary machine variant. |
| Chapter | A coherent functional or structural advance. |
| Lesson | The smallest unit with one complete learning objective. |
| Assembly Step | One observable learner action that changes the constructed state. |
| Knowledge Concept | An idea needed to understand a function, relation, property, cause, or design choice. |
| Representation | A visual, spatial, textual, audible, or interactive way to perceive a semantic entity. |
| Check | An activity that gathers evidence of reasoning or understanding. |
| Course Progress | Durable facts about where the learner can resume and what has been completed. |
| Tutor Context | A bounded projection of current course state, visible elements, prior presentation, and relevant evidence. |

## Non-negotiable distinctions

- A machine is not its representation.
- A component is not a mesh or visual piece.
- Assembly reveals structure and relationships; it does not imply complete
  physical simulation.
- The knowledge graph organizes explainable knowledge; the course selects and
  orders a scoped path through it.
- A lesson is an educational unit; an assembly step is one action within it.
- Progress records observable facts; it is not proof of an internal mental
  state.
- Tutor context is a projection, not an independent source of truth.

## Core invariant

Every element shown or requested from the learner must contribute to explaining
the primary machine's function within the course's declared scope.

## Natural systems and fundamental ingredients — creator clarification, 2026-10-11

The intended learning scope includes natural functional systems such as atoms,
not only human-designed devices. Function denotes observable behavior and
relationships; it need not mean an intentionally assigned purpose. Construction
must expose the constituent prerequisites of later materials and mechanisms.
An experimentally elementary ingredient may serve as a declared starting unit:
do not invent its subcomponents to satisfy recursive assembly. Exact runtime
representation of that boundary remains unimplemented. See
[Origin journey](origin-journey.md) for the scientific scope and proposed path.

## Shared constructive dependencies — accepted direction, 2026-10-11

A construction journey can share prerequisites across destination Courses.
Branches may meet again; a completed core process is reused without mandatory
quantity repetition. Constituent structure, formation processes and historical
order remain distinct relations. Fundamental ingredients have an explicit
evidence boundary rather than invented recursive subcomponents. This direction
is accepted in [0008](../decisions/0008-constructive-foundation-and-shared-branches.md);
exact cross-Course runtime contracts remain unimplemented.
