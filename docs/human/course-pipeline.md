# Course Pipeline

> Detailed counterpart: [LLM course pipeline](../llm/course-pipeline.md)

The pipeline turns one real machine variant into a validated, maintainable
learning experience. The product includes both the course and the capability to
produce excellent courses repeatedly.

## Governing rule

A stage advances because its output satisfies an evidence-backed gate, not
because time was spent. When a problem appears, correction returns to the stage
that created its cause.

## Fifteen stages

| Stage | Decision or result |
| --- | --- |
| 1. Select | Choose a machine worth investigating. |
| 2. Scope and research | Fix one exact variant, boundary, evidence base, and uncertainty set. |
| 3. Decompose | Model components, relations, flows, and justified depth. |
| 4. Build knowledge | Connect claims, concepts, prerequisites, terminology, and evidence. |
| 5. Design learning | Define outcome, chapters, lessons, objectives, and checks. |
| 6. Design assembly | Specify each action, state transition, hint, error response, and meaning. |
| 7. Prototype | Test the entire course at low fidelity before expensive production. |
| 8. Produce representations | Create reviewed semantic geometry, views, motion, connections, and interactions. |
| 9. Author content | Write timely explanations and reasoning checks. |
| 10. Prepare tutor | Define grounded context, policy, limits, and evaluation cases. |
| 11. Integrate | Compile one executable and resumable course path. |
| 12. Validate | Verify domain, pedagogy, interaction, accessibility, tutor, and progress quality. |
| 13. Pilot | Observe representative learners and gather evidence of understanding. |
| 14. Release | Publish an identifiable, recoverable, approved revision. |
| 15. Maintain | Observe, correct, revalidate, and preserve history. |

## Current gate

Machines is before Stage 1 completion. The next work is to compare candidate
reference machines, select one, and then define its exact variant.

## Reference-course rule

The complete course must first exist at low fidelity. Only then should Machines
build the minimum native engine needed to execute that validated path. The
course tests the pipeline; the engine tests which abstractions deserve to
become durable.
