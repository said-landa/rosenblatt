# Architecture

> Detailed counterpart: [LLM architecture](../llm/architecture.md)

The architecture is currently a planning contract. It identifies durable
boundaries without pretending that the final implementation is known.

## Architectural thesis

All authoring, compilation, runtime, tutor, observation, and maintenance
capabilities should derive from one shared Machines semantic reality.
Integration means shared identity, meaning, provenance, versions, and impact
rules—not merely APIs between unrelated tools.

## Three planes

| Plane | Responsibility |
| --- | --- |
| Authoring and research | Establish evidence, model machines, design learning, author representations and tutor behavior. |
| Compilation and validation | Resolve references, enforce invariants, build immutable course packages, and produce diagnostics. |
| Execution and observation | Run an exact course revision, preserve progress, support contextual tutoring, and record bounded observations. |

## Shared semantic substrate

The substrate connects:

- machine identity, variants, components, and relations;
- claims, evidence, concepts, and terminology;
- course structure, objectives, steps, and checks;
- representations, camera intent, and interaction;
- tutor policy and evaluation;
- progress, session state, observations, and interpretations;
- builds, pilots, releases, and maintenance history.

## Important boundaries

- Logical identity differs from immutable revision identity.
- Authored records differ from compiled projections.
- Durable progress differs from transient session state.
- Observations differ from interpretations about learning.
- A pilot execution differs from a published release.
- Explanations designed into a course differ from proposals generated by a
  tutor at runtime.

## Build direction

The first native implementation should be the minimum vertical system required
to execute the validated reference course. Final engine and tool boundaries
remain hypotheses until real course work exposes them.

The product engine itself will be Machines-native rather than based on a
generic game engine. This decides the foundation and semantic ownership while
leaving its internal architecture, rendering backend, and capability order open
to evidence. See [Decision 0003](../decisions/0003-machines-native-engine-foundation.md).
